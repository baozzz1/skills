## 一句话定位

Agent 循环是一个**只做六件事的状态机**：读消息、想下一步、要么调工具、要么要更多信息、要么直接回答、否则收尾。其它所有花活都是这六步的组合。

<Callout kind="tldr">
  Agent ≠ "聊天机器人套了 tool-use"。它是一个**多轮收敛**循环：每一轮都允许工具调用 / 自我修正 / 继续推理，直到产出一个用户可见的最终回复或触发兜底条件。
</Callout>

## 实现风格对比

同一个 agent loop，三种风格在可观测性上差别巨大：

async function loop(messages) {
  let state: State = 'gen';
  while (state !== 'done') {
    state = await transition(state, messages);
  }
  return finalText(messages);

<Callout kind="warning">
  三种写法**外层等价**，在出错诊断 / 可观测 / 可中断三件事上差异很大。**生产优先状态机**，原型阶段 while 够用，递归只在教学里用。
</Callout>

## 哪些事不在这个循环里

<Chip tone="muted">不属于 agent loop</Chip>

- **流式输出**：text token 的流式渲染是 step 2 内部的事，循环不感知
- **记忆 / RAG**：检索是工具的一种实现，对循环来说就是"调了个 tool"
- **多模态**：图片 / 音频 在 message 里以 part 形式存在，对循环逻辑无影响
- **Plan + Execute**：把 step 3 替换成"先生成 plan、再分步执行"——是 step 3 的内部花活，不改外层

> 一句话：**所有"高级 agent 模式"几乎都是 step 3 内部的事**。外层六步是稳定的。
