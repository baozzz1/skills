## One-line positioning

The agent loop is a **state machine that does only six things**: read messages, think a next step, either call tools, ask for more info, answer directly, or close out. Every higher pattern is a composition of these six.

<Callout kind="tldr">
  An agent ≠ "a chatbot wearing tool-use." It's a **multi-turn convergent** loop: each turn permits tool calls / self-correction / continued reasoning, until it produces a user-visible final reply or hits a guardrail exit.
</Callout>

## Implementation styles

The same agent loop, three styles — observability differs sharply:

<Callout kind="warning">
  All three are **outwardly equivalent**, but differ sharply on debuggability / observability / interruptibility. **Production should prefer state machines**; while-loops are fine for prototypes; recursion is for teaching.
</Callout>

## What's not in this loop

<Chip tone="muted">not part of the agent loop</Chip>

- **Streaming output**: text-token streaming happens inside step 2; the loop doesn't observe it
- **Memory / RAG**: retrieval is a tool implementation; to the loop it just looks like "called a tool"
- **Multimodal**: images / audio live inside message parts; loop logic is unchanged
- **Plan + Execute**: replaces step 3 with "plan, then execute step-by-step" — internal to step 3, doesn't change the outer six

> One line: **almost every "advanced agent pattern" is internal to step 3**. The outer six steps are stable.
