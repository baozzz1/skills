# 杂谈写作三步法

好稿子都有两个观点：一个用来出发（**起点观点**），一个用来抵达（**终点观点**）。第一步把两个观点找出来，第二步修一条从起点到终点的路，第三步看这条路别人走得怎么样。

> 方法出处：B 站 UP 主「演播室外有一堆屎蛋」（https://space.bilibili.com/399454895/dynamic），详见同目录 `README.md`。

## 分工（先读这段）

- **观点和经历归作者。** 第一反应、情绪、亲身经历只能来自用户。用户没说出自己的第一反应、也没拒绝来回确认时，这一轮停在 1.1 问，不写正文。
- **事实归你。** 勘误表里能查的你去查（有搜索工具就用），查完给结论和出处；查不到的标「未核实」。不要把核对推给用户。
- **用户要你写正文：** 先拿到一句话论点（可以给 2–3 个候选让用户挑），骨架给用户过目后再写正文。
- **用户明确拒绝来回确认（「别问了」「今晚就要发」）：** 只有这种情况由你推断论点。一次交付：回复开头一句写明你推断的起点和终点，请用户不对就换；勘误照做；正文按骨架写。
- 无论哪种，正文里的第一人称经历只用用户给过的，缺的留 `【TODO：你的经历——xxx】`。

## 从哪一步进

还没下笔的（下表前两行），先读 `~/.zatan-xiezuo/retro.md`：里面有上几篇记下的问题，就提醒作者。

| 用户手里有什么 | 从哪开始 |
|---|---|
| 只有题目或一个念头 | 一、下笔前 |
| 有一句话论点，没结构 | 补做 1.3 勘误、1.4 定位，再进二 |
| 有成稿要审 | 审稿 |
| 已经发出去了 | 三、出产后 |

## 一、下笔前：把「我想说什么」找到并验过

**1.1 自我观点察觉**：问作者：对这件事，你的第一反应是什么？是情绪（「这也太傻逼了」）还是事实（「这设定跟原著不符」）？把第一反应不加修饰写成一句话。这句是候选观点，不急着护它。

**1.2 观察（第三人称校验）**：把这句话放到第三人称视角下，跟事实对撞：哪里对得上，哪里打架。你负责列出对撞结果（事实附出处）；打架怎么处理由作者选，只有两种：修观点；或者矛盾本身就是题眼，挖到了更深一层。
例：「金刚狼没有男人味」撞上「漫画金刚狼恰恰是自洽的祖师爷」→ 矛盾浮出：不是他没有男人味，是这游戏把能动性换成了受害性。

**1.3 资料补充（勘误）**：两栏勘误表——我知道什么 / 我不知道什么。不知道的要么查，要么在稿里如实标「我不知道」。认知不需要深，需要诚实；拿水凑深是投稿最常见死因。涉及厂商关系、设定、数据的说法，先核实再立论，核心观众会逐帧查。

**1.4 观点位置考察（整套方法论的发动机）**：判断那句话是起点还是终点。
- 是终点 → 问它够不够深：是情绪指控，还是能再翻一层成结构归因？
- 是起点 → 它顶不住勘误也没关系，它的职责是拉人进门；但得修一条论证链把它送到终点。

**交付物**：一句话论点（写清起点是什么、终点是什么）+ 两栏勘误表。

## 二、下笔中：先想效果，再钉骨架，后填细节

**2.1 文体察觉（先认发动机，再选文体）**：从情绪还是事实出发？从结论还是过程出发？

| | 结论 | 过程 |
|---|---|---|
| **情绪** | 吐槽立论型 | 体验还原型 |
| **事实** | 论证型 | 考据科普型 |

发动机决定文体，别让文体拧着发动机。

**2.2 逻辑大纲（三层）**

1. **先列「想要的东西」**，不管顺序不管逻辑：观众的情绪想怎么引导（哪里暴躁、哪里安静、哪里顿悟）；有哪些观点想表达；有什么特别好笑、不展示可惜的包袱。
2. **钉骨架**：把想要的东西排成一副自洽的骨架，逻辑自洽、情绪自洽。骨架不会一稿过，它的价值就是拿来删改：动一处看全身，塌了就重排，别心疼。硬规矩：
   - 顿悟句只许出现在结尾；
   - 删包袱前先查它被哪里 callback；
   - 桥段别超过一成。
3. **填细节**：素材、包袱、过渡往骨架上填。修好的标志：每段只剩一个问题要回答。

**交付物**：一副能删改的骨架。给用户看的格式：按段编号，每段写「这段回答的问题 / 情绪位置 / 放哪些素材和包袱」。

## 审稿

1. **先认发动机**：用 2.1 的表给稿子定位，按它自己的文体提意见：留强项、换弱项，别把所有作者压成自己。
2. **找两个观点**：指出起点观点和终点观点各是哪句；找不到，这就是第一条意见。
3. **对硬规矩**：顿悟句在不在结尾、包袱有没有被 callback、桥段占比、每段是不是只回答一个问题。
4. **过勘误**：稿里的事实断言（数据、引语、厂商关系、设定）逐条列出，能查的查，查不到的标出来。
5. **排序**：动骨架的意见在前，改细节的在后。

## 三、出产后

不用细写，就两件事：

1. 享受观众的夸奖和互动——评论区本来就是情绪峰值该在的地方；
2. 问作者「这篇不好的地方是哪」，把答复原话追加到 `~/.zatan-xiezuo/retro.md`（没有就新建），新的在上，一行一条：`- YYYY-MM-DD《篇名》：不好的地方（作者原话）`。下一篇下笔前会读到。

方法论到这里是个环：出产后发现的问题，就是下一篇第一步的素材。

## 常见翻车

| 翻车 | 改法 |
|---|---|
| 用户说「帮我写一篇」，直接交出整篇成稿，观点是你替用户想的 | 第一轮只做 1.1：问第一反应；用户明确拒绝来回确认时，按「分工」一次交付并写明推断的论点 |
| 替作者编第一人称经历 | 只用用户给过的，缺的留 TODO |
| 事实核查放在文末「建议你核对」，或凭记忆下定论不给出处 | 下笔前做勘误表，能查的自己查，结论附出处 |
| 顿悟句埋在中段，结尾用「见仁见智」收 | 把顿悟挪到结尾 |
| 审稿时把体验还原型改成论证型 | 先认发动机，顺着它的文体改 |
